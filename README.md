# aube bug reproductions

Minimal test cases for bugs found migrating a large monorepo from pnpm to aube. Each directory is self-contained with a README explaining the bug, reproduction steps, and expected vs actual behavior.

GitHub Actions workflows compare aube against pnpm for each repro.

## Expected behavior / config gap

### 8. `exotic-git-dep-resolution/`

`@electron/rebuild` depends on `@electron/node-gyp` via a git URL. aube blocks
this by default via `blockExoticSubdeps`. Set `blockExoticSubdeps: false` in
`pnpm-workspace.yaml` to allow it.

## Open (as of 1.4.0)

### 9. `patch-application-failure/` — patch fails despite matching pre-image hash

A pnpm-generated patch for `gifuct-js@2.1.2` applies correctly with pnpm but
fails with aube ("error applying hunk #1"). The installed file's git blob hash
matches the patch's pre-image hash exactly (`fb0b487b...`), confirming the file
is correct and the patch should apply cleanly.

### 10. `catalog-npm-alias/` — npm: aliases from catalog not installed from pnpm lockfile

When a catalog entry uses an `npm:` alias (e.g. `beamcoder: npm:beamcoder-prebuild@0.7.1-rc.18`)
and the lockfile is generated by pnpm, `aube install --frozen-lockfile` accepts the lockfile
but silently does not install the aliased package. aube generates its own lockfile and installs
the alias correctly — the bug is specific to reading a pnpm-generated lockfile.
