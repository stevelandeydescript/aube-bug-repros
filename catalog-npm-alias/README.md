# Bug: npm: aliases from catalog not installed when reading pnpm-generated lockfile

## Summary

When a catalog entry uses an `npm:` alias (e.g. `beamcoder: npm:beamcoder-prebuild@0.7.1-rc.18`)
and the lockfile is generated by pnpm, aube's `--frozen-lockfile` accepts the lockfile but does
not install the aliased package. The package is completely absent from `node_modules`.

aube generates its own lockfile and installs the alias correctly. The bug is specific to reading
a pnpm-generated lockfile.

## Steps to reproduce

```sh
pnpm install                              # generates lockfile, installs beamcoder
rm -rf node_modules packages/app/node_modules
aube install --frozen-lockfile            # accepts lockfile, but beamcoder is missing
ls packages/app/node_modules/beamcoder    # does not exist
```

## Expected

`beamcoder` (aliased to `beamcoder-prebuild`) is installed in `packages/app/node_modules/`.

## Actual

`packages/app/node_modules/beamcoder` does not exist. aube reports "Already up to date"
without error but the package is silently missing.

## Versions

- aube 1.4.0
- pnpm 10.33.0 (works correctly)
